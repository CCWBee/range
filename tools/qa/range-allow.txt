# RANGE touch layer: the deliberate exceptions to the mechanical scan, and nothing else.
# Each line is "<path suffix> :: <text the finding contains>". A new suspect is either a mistake or
# a line for this file with a written reason; the scanner is never widened.
#
# What changed since the first pass, and why the file is shorter. The palette's own declarations now
# live in screenshots/qa/tokens.css, which tools/qa_touch.mjs writes beside touch.css, so the colour
# rule in tools/qa/range-tokens.json admits a var() and nothing else and a literal can no longer pass
# itself off as a token. The one light, the lamps, the knurling, the etched scale, the hatch, the
# machined face and the three-stop text shadows of a lit and a locked legend are declared there as
# tokens too, so sections 1, 2 and 3 of section 8's list below no longer reach the scanner at all and
# carry no line here. That took the run from 134 suspects to 43.
#
# Section 8 of docs/specs/2026-09-10-range-touch-cockpit.md names six exceptions. Sections 7 and 8
# below are beyond them: the spec's own CSS in sections 2.3, 2.4, 3.5, 3.12, 3.15, 6 and 10.2
# produces suspects that none of the six covers, so the gate cannot be reached on six alone. They are
# recorded here with their reasons rather than left as a red gate, and they want Charles's ruling.

# 1. The panel's five-stop shadow (section 2.3). Written across two lines with its colours as
#    tokens, so the scanner's box-shadow rule, which needs the semicolon on the same line, never
#    sees it and no line is needed here.

# 2. The cap's five-stop shadow (section 2.3): the lit top rim, the left rim, the shaded bottom
#    edge, the 0 1px 0 line that is the bezel catching light just below the cap, and the drop. Also
#    written across two lines. The pressed cap's two-stop inversion is the same object under the
#    same light and is the one shadow on the layer the scanner sees whole.
qa/touch.css :: inset 0 2px 3px var(--slot-shade),inset 0 -1px 0 var(--slot-lip)

# 3. The three-stop text shadows of a lit legend and of a locked one (section 2.3): core, 1 px
#    fringe and bloom are what read as a legend lit from behind rather than as coloured text. They
#    are --lit-glow, --lit-glow-warming and --lock-glow in tokens.css and reach the scanner as a
#    var(), so no line is needed here either.

# 4. The backdrop-filter on the panel and on a cap, and nowhere else (sections 1.1 and 11.3): the
#    quadrant carries 14 px and each of the three caps 8 px, one layer of glass per control, which is
#    what removes the glass on glass. Two needles, one per surface, so the other backdrop-filter
#    suspects are not allowed by them. The cap's blur is section 11's decision: the bezel went, so a
#    cap is no longer painted on a panel and has to be its own glass or it is nothing.
qa/touch.css :: var(--panel-backdrop)
qa/touch.css :: var(--cap-backdrop)

# 5. The canopy bands and the intro veil (sections 2.1, 3.1 and 10.1): they hold their alpha flat
#    for the depth or the width the text occupies and only then decay, which is the structural answer
#    to white text on a light background. The --metal gradient of the lever and the knob is now
#    --metal-face in tokens.css and needs no line.
qa/touch.css :: var(--veil-top)
qa/touch.css :: var(--veil-bottom)
qa/touch.css :: var(--veil-intro)

# 6. The upper-case tracking on every legend (section 2.2): the type scale sets .08em to .26em on
#    every legend, numeral and readout, so tracking is the design rather than an exception to it.
qa/touch.css :: tracked label

# 7. Beyond section 8's six. The rest of the layer's backdrop-filter suspects, which are not the
#    panel: the two @supports feature tests that section 6's fallback ladder is built on, the
#    declaration that switches the blur off under reduced transparency, and #rotate's own 18 px blur,
#    which section 3.15 specifies because it is the one surface allowed to go nearly opaque. And the
#    stall flash, which is DESIGN.md's standing rule that the stall is the one thing that flashes,
#    and which stops under prefers-reduced-motion two rules later.
qa/touch.css :: @supports ((backdrop-filter:blur(1px))
qa/touch.css :: @supports not ((backdrop-filter:blur(1px))
qa/touch.css :: .panel{-webkit-backdrop-filter:none
qa/touch.css :: .key,body.touch #start{-webkit-backdrop-filter:none
qa/touch.css :: #rotate{display:none
qa/touch.css :: animation:stall-flash

# 8. Beyond section 8's six: the machined internals. Section 2.4 declares the layout rhythm as
#    4, 7, 14, 22, 32, and then dimensions the panel's insides from the object rather than from that
#    rhythm: a cap's 5 px padding either side of a 54 px legend, the slot's 6 px gutter and the gate
#    column's 6 px, the knob's 2 px seat and the throttle numeral's 2 px, the 8 px inset of the
#    knurling on a 36 px lever and a 26 px knob, the slot's own 19 px end stops (the lever is 22 px tall and centred
#    on the travel, so anything less hangs it off the panel), the telemetry group's 5 px and the
#    switch's 10 px, the 8 px gutter between the three 62 px caps of section 11.2 (dimensioned from
#    the column: 3 x 62 plus 2 x 8 is the 202 px that clears #touchTop above and the frame edge
#    below at every verification height), and a plain text control's 14 by 12 padding around a 44 px
#    target. These are
#    dimensions of the machined object, not steps of the spacing scale, which is why they are here
#    rather than added to range-tokens.json: the token file stays equal to section 2.4's declared
#    scale verbatim.
qa/touch.css :: ;gap:5px;
qa/touch.css :: ;gap:8px;
qa/touch.css :: ;gap:10px;
qa/touch.css :: ;padding:0 2px;
qa/touch.css :: ;padding:0 5px;
qa/touch.css :: ;padding:14px 12px;
qa/touch.css :: ;top:2px;
qa/touch.css :: ;left:6px;
qa/touch.css :: ;left:8px;
qa/touch.css :: ;right:6px;
qa/touch.css :: ;bottom:19px;
